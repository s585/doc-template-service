# План реализации API печатных форм

Дата: 2026-03-10

## Назначение

Этот файл фиксирует пошаговый план реализации API сервиса печатных форм.
План нужен для итеративной работы и сохранения контекста по мере проработки и реализации задачи.

## Текущий статус

- DTO для `TemplateMapping`, `TemplateCreationRq`, `TemplateUpdateRq`, `TemplateRs`, `Expression`, `ValueSource` уже заведены в `api`-модуле
- соглашения по mapping и expression зафиксированы в `docs/template-mapping-agreements.md`
- схема `t_template_mapping` приведена к хранению `key` и JSON-описания маппинга в `definition JSONB`
- комментарии по changelog в `db`-модуле приведены к русскому языку и покрывают все колонки
- `Шаг 1` выполнен: API-контракты зафиксированы в `TemplateController`
- `Шаг 2` выполнен: модель хранения синхронизирована с контрактами API

## Шаг 1. Зафиксировать финальные API-контракты

Статус: выполнено

Нужно определить и утвердить:

- сигнатуры контроллеров для:
  - `POST /v1/doc/template/import`
  - `PUT /v1/doc/template/{templateId}`
  - `DELETE /v1/doc/template/{templateId}`
  - `POST /v1/doc/template/list`
  - `POST /v1/doc/{entityId}/{objectId}/template/list`
- коды ответов
- формат ошибок `400`
- состав request/response DTO на каждом endpoint

Результат шага:

- интерфейс(ы) API в `api`-модуле
- понятный контракт для `impl`-реализации

## Шаг 2. Довести модель хранения до контрактов

Статус: выполнено

Нужно синхронизировать:

- `t_template`
- `t_template_mapping`
- API DTO
- будущую доменную модель

Нужно отдельно закрыть:

- хранение `description`
- преобразование `active` без промежуточного `status`
- использование `code` без промежуточного `system_name`
- соответствие `s3_key <-> s3Key`

Результат шага:

- понятная схема хранения всех полей `TemplateRq`/`TemplateRs`

## Шаг 3. Зафиксировать формат хранения JSON-полей

Статус: выполнено

Нужно определить, как именно сериализуются:

- `TemplateMappingDefinition` в `t_template_mapping.definition`
- `displayCondition` в `t_template.display_condition`

Нужно решить:

- используем ли прямую Jackson-сериализацию DTO
- вводим ли отдельную domain-модель для хранения
- как валидируем совместимость JSON и DTO

Результат шага:

- единое правило сериализации/десериализации для JSONB-полей

## Шаг 4. Реализовать слой доступа к данным

Статус: выполнено

Нужно создать DAO/репозитории для:

- шаблонов
- маппингов
- условий отображения
- удаления связанных записей
- выборки списков с фильтрацией

Результат шага:

- рабочий persistence-слой для всех use case

## Шаг 5. Реализовать import use case

Статус: выполнено

Нужно сделать:

- прием multipart запроса
- прием `TemplateCreationRq`
- валидацию формата файла `DOCX/XLSX`
- проверку уникальности `code`
- создание или поиск папки в filestorage
- загрузку файла в filestorage
- парсинг placeholders
- построение `TemplateMapping`
- сохранение шаблона, mapping и condition
- формирование `TemplateRs`

Результат шага:

- рабочий `POST /v1/doc/template/import`

## Шаг 6. Реализовать update use case

Статус: выполнено

Нужно сделать:

- загрузку текущего шаблона
- полное обновление по `TemplateUpdateRq`
- отдельную обработку:
  - `displayCondition`
  - `templateMapping`
  - `active`
  - `description`
  - `name`
- сохранение изменений
- формирование `TemplateRs`

Результат шага:

- рабочий `PUT /v1/doc/template/{templateId}`

## Шаг 7. Реализовать delete use case

Статус: выполнено

Нужно сделать:

- удаление файла из filestorage/S3
- удаление `template`, `mapping`, `condition`
- возврат `204 No Content`

Результат шага:

- рабочий `DELETE /v1/doc/template/{templateId}`

## Шаг 8. Реализовать list use case

Нужно сделать:

- прием `CommonRqDto`
- поддержку фильтров:
  - `active`
  - `entityId`
  - `name`
  - `description`
  - `format`
- получение списка шаблонов
- формирование массива `TemplateRs`

Результат шага:

- рабочий `POST /v1/doc/template/list`

## Шаг 9. Реализовать список шаблонов с учетом displayCondition

Нужно сделать:

- выборку шаблонов по `entityId`
- получение данных по `objectId`, необходимых для вычисления условий
- вычисление `displayCondition`
- фильтрацию доступных шаблонов

Результат шага:

- рабочий `POST /v1/doc/{entityId}/{objectId}/template/list`

## Шаг 10. Подготовить инфраструктуру для mapping

Нужно сделать:

- парсинг placeholders из шаблона
- валидацию `source`, `path`, `referenceValuePath`, `expression`
- сериализацию и десериализацию `TemplateMapping`
- базовые правила проверки корректности mapping на API-уровне

Результат шага:

- инфраструктура, на которую можно опираться в import/update и дальше в генерации документа

## Шаг 11. Реализовать мапперы между слоями

Нужно сделать преобразования:

- DB <-> domain
- domain <-> API DTO
- `status <-> active`
- `system_name <-> code`
- `s3_key <-> s3Key`

Результат шага:

- предсказуемые и изолированные преобразования моделей
