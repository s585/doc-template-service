# Порядок выполнения пунктов плана (MVP) и зависимости

1. Уточнение границ MVP
   - Зависимости: нет
   - Входит (must-have):
     - CRUD шаблонов: создать/обновить/получить/удалить шаблон
     - Хранение файла шаблона в S3 через `saas-file-storage`
     - Сохранение `template_variable` (переменные + маппинг) отдельным запросом
     - Получение и обработка состояния бизнес-объекта для вычисления значений переменных
     - Парсинг файла шаблона на этапе генерации
     - Генерация документов по шаблону (только асинхронно) + ограничение параллелизма
     - Базовый expression engine для простых условий/выражений
     - Минимальная наблюдаемость: метрики/логи по генерациям и ошибкам
   - Не входит:
     - Синхронная генерация
     - Сложные шаблонные конструкции (циклы/advanced формулы)
     - Визуальный редактор шаблонов
     - Мульти-форматная генерация (например, DOCX->PDF/HTML) — только один формат
     - Версионирование шаблонов и откаты
     - Высоконагруженный масштабируемый режим (выделенный сервис генерации) — только подготовка
     - Расширенные ACL/ролевая модель (кроме минимально необходимой)
   - Флоу (MVP):
     - Создать шаблон и загрузить файл в S3
     - Сохранить `template_variable` отдельным запросом
     - Получить и обработать состояние бизнес-объекта
     - Запустить генерацию (парсинг на этапе генерации)
2. Модель данных и хранилища
   - Зависимости: 1
   - Уточнить, что `template_variable` = переменные + маппинг (expression/value_type/is_required)
   - Зафиксировать минимальные поля и enum-значения (format/status)
   - Проверить связи и каскады (template -> variables/conditions)
   - Согласовать read-model для UI: `generated_document` + `generated_file`
   - Подтвердить RLS и индексы (tenant_id, request_uid, status)
   - Определить уникальные ограничения (template_id + code, tenant_id + request_uid)
   - Подтвердить жизненный цикл статусов (template_status, generated_file_status, job_status)
   - Проверить nullable-поля и порядок заполнения (s3_key, checksum, size_bytes)
   - Уточнить требования к `entity_id` и `entity_object_id` (формат, длина, индекс)
   - Решить, нужен ли отдельный атрибут для владельца/инициатора (created_by)
3. API контракты (CRUD шаблонов + CRUD `template_variable` + генерация async)
   - Зависимости: 1, 2
   - CRUD шаблонов: список/получение/создание/обновление/удаление
   - Отдельный endpoint для `template_variable` (создать/обновить/получить список)
   - Генерация: создать запрос, получить статус, получить результат
   - Идемпотентность: `request_uid` для повторных запросов
   - Ошибки и валидации (формат, переменные, доступ)
   - Определить контракты DTO (request/response) и обязательные поля
   - Уточнить пагинацию/фильтры (по entity_id, status, created_at)
   - Политика удаления: soft delete vs hard delete для template
   - Формат ошибок (код/сообщение/детали), единый для всех endpoints
   - Ограничения на размер/кол-во переменных в одном запросе
4. Интеграция с S3 через `saas-file-storage`
   - Зависимости: 2, 3
   - Upload template file: ключи, метаданные, retry/timeout
   - Чтение файла на генерации
   - Хранение артефактов генерации (generated_file.s3_key)
   - Политики доступа/TTL, если применимо
   - Контракты с `saas-file-storage` (создание, получение, удаление)
   - Валидация формата файла (DOCX/XLSX) до сохранения
   - Обработка ошибок S3 и ретраи (коды, лимиты, бэкофф)
   - Управление коллизиями ключей и повторной загрузкой
5. Expression engine (для вычисления значений переменных из бизнес-объекта)
   - Зависимости: 1
   - Минимальный набор операторов и функций
   - Формат хранения expression (jsonb) и валидация
   - Выполнение в контексте бизнес-объекта
   - Типизация результатов (value_type) и правила приведения
   - Обработка null/отсутствующих полей
   - Ограничения на глубину/сложность выражений
   - Тестовые наборы выражений (позитив/негатив)
6. Получение и обработка бизнес-объекта для вычисления значений переменных
   - Зависимости: 3, 5
   - Источник данных (API/БД/сервис)
   - Нормализация/обогащение данных под expression engine
   - Обработка ошибок отсутствующих/невалидных полей
   - Таймауты и политика повторов при обращении к источнику
   - Кэширование/батчинг (если требуется)
   - Контроль прав доступа к бизнес-объекту
7. Генерация документов (core + асинхронная оркестрация, включает парсинг шаблона и ограничение параллелизма)
   - Зависимости: 4, 5, 6
   - Парсинг шаблона на этапе генерации
   - Подстановка значений и формирование результата
   - Асинхронная очередь/worker, ограничение параллелизма
   - Обновление статусов `generated_document`/`generated_file`
   - Идемпотентность генерации (request_uid)
   - Стратегия обработки ошибок (retry, mark ERROR)
   - Гарантии консистентности между `generation_job` и read-model
   - Ограничения на размер шаблона/объекта данных
8. Наблюдаемость и контроль нагрузки
   - Зависимости: 7
   - Метрики: время генерации, ошибки, очередь, параллелизм
   - Логи по запросам и задачам
   - Алерты на рост ошибок/времени
   - Корреляция запросов (request_uid/job_id)
   - Трассировка критических путей (fetch object -> evaluate -> generate)
9. Подготовка к выделению генерации в отдельный сервис
   - Зависимости: 3, 7
   - Стабильные контракты между API и генерацией
   - Минимизация прямых зависимостей на БД
   - Документация точек интеграции
   - Определить границы ответственности (кто пишет read-model)
   - Договориться об интерфейсе очереди/событий
10. Тестирование
   - Зависимости: 6, 7
   - Юнит тесты: expression engine, маппинг, парсер
   - Интеграционные: S3, генерация, async оркестрация
   - Негативные сценарии: отсутствующие переменные, ошибки источника
   - Нагрузочные сценарии (параллельные генерации)
   - Проверка RLS/tenant изоляции
11. Документация
   - Зависимости: 3, 7, 8
   - API контракты и примеры запросов
   - Флоу генерации и статусы
   - Требования к данным бизнес-объекта
   - Описание expression engine (операторы, примеры)
   - Диагностика и типовые ошибки
